# Git MCP для Codex

Плагин объединяет локальные инструменты Git через MCP и навыки Codex. Сервер работает через stdio и запускает Git отдельным процессом без shell. Ключ OpenAI API и отдельный HTTP-сервис не нужны.

## Установка в Codex

Нужны **Node.js 20+**, **Git 2.28+** и актуальный Codex с поддержкой плагинов. Готовый плагин находится в `plugins/git-mcp/`, сборка с зависимостями — в `plugins/git-mcp/dist/server.cjs`: после клонирования устанавливать npm-пакеты для использования плагина не требуется.

Из корня этого репозитория:

```sh
codex plugin marketplace add .
codex plugin add git-mcp@git-mcp-local
```

В Codex Desktop откройте каталог плагинов, выберите источник **Git MCP — Local** и установите **Git MCP**. Если источник ещё не появился, перезапустите приложение. Начните новый локальный чат в целевом репозитории. В доверенных проектах каталог `.agents/plugins/marketplace.json` также позволяет обнаружить плагин из репозитория.

Чтобы использовать плагин в другом проекте, добавьте каталог по абсолютному пути:

```sh
codex plugin marketplace add /absolute/path/to/git-mcp
codex plugin add git-mcp@git-mcp-local
```

Обновления исходников требуют пересборки и обновления установленной копии плагина. Наличие каталога плагинов в репозитории само по себе не включает сервер для других проектов.

Примеры запросов:

- «Используй git-inspect: объясни состояние репозитория и последние изменения».
- «Используй git-review: проверь изменения ветки относительно main».
- «Используй git-commit: проверь и закоммить изменения этой задачи».

Точные имена навыков в интерфейсе могут включать пространство имён плагина. Codex обнаруживает навыки автоматически; выбрать их явно можно через меню навыков. Навыки отвечают на языке пользователя.

## Инструменты

Каждый вызов принимает обязательный **`repo_path` — абсолютный путь к рабочему дереву Git**. Пути `paths` отсчитываются от корня этого репозитория, даже если `repo_path` указывает на подкаталог. Рабочие деревья `git worktree` поддерживаются, bare-репозитории не поддерживаются.

| Инструмент | Назначение |
| --- | --- |
| `git_status` | Ветка, HEAD, изменённые файлы, отпечаток индекса |
| `git_diff` | Diff рабочего дерева, индекса или диапазона коммитов |
| `git_log` | История: по умолчанию 20, максимум 100 коммитов |
| `git_show` | Метаданные и patch отдельного коммита |
| `git_branches` | Локальные и уже известные remote-tracking ветки |
| `git_add` | Добавление явно указанных путей в индекс |
| `git_unstage` | Удаление выбранных изменений из индекса с сохранением рабочих файлов |
| `git_commit` | Локальный коммит проверенного индекса |
| `git_create_branch` | Создание локальной ветки без переключения |
| `git_switch_branch` | Переключение на существующую ветку при чистом рабочем дереве |

Успешный ответ содержит JSON в `structuredContent` и дублирует его в текстовом содержимом MCP. Ошибки операций возвращают `isError: true` и JSON с `code` и `message`. Некорректные параметры отклоняются SDK по схеме.

Пример просмотра staged diff:

```json
{
  "repo_path": "/absolute/path/to/project",
  "mode": "staged"
}
```

Для `git_commit` передайте `message` и **`expected_index_fingerprint`** из ответа на просмотр полного staged diff. Если индекс изменился, сервер вернёт `INDEX_CHANGED`; сначала нужно заново прочитать и проверить staged diff. Отпечаток проверяется непосредственно перед коммитом, но не блокирует другие процессы Git: во время коммита избегайте параллельной записи в индекс.

Для сравнения веток используйте `git_diff` с `mode: "range"`, `base` и необязательным `head` (по умолчанию `HEAD`). `merge_base: true` по умолчанию сравнивает с общим предком; `false` сравнивает конечные состояния. Untracked-файлы перечислены в статусе, но их содержимое не входит в diff.

## Подключение только MCP

Для Codex CLI без установки навыков:

```sh
codex mcp add git -- node /absolute/path/to/git-mcp/plugins/git-mcp/dist/server.cjs
```

Для другого MCP-клиента используйте его конфигурацию stdio:

```json
{
  "mcpServers": {
    "git": {
      "command": "node",
      "args": ["/absolute/path/to/git-mcp/plugins/git-mcp/dist/server.cjs"]
    }
  }
}
```

`${PLUGIN_ROOT}` из `plugins/git-mcp/mcp.json` подставляет хост плагинов Codex. При ручной настройке другого клиента замените его абсолютным путём.

## Границы выполнения

- Нет универсального `git_run` и инструментов для fetch, pull, push, reset, clean, amend, удаления веток и force-переключения.
- Пути передаются буквально: `*.txt` означает имя файла, а не шаблон. Для записи нужен непустой список выбранных путей; корневой путь `.` не принимается. Выбранный каталог включает его содержимое.
- Ревизии проверяются и преобразуются в хеши коммитов до использования; опции вместо ревизий отклоняются. Переменные окружения `GIT_*` не могут перенаправить операцию в другой репозиторий.
- Git hooks, fsmonitor, внешние diff/textconv и подпись коммитов отключены. Коммиты **не подписываются**. Обязательные проверки проекта выполняет Codex перед коммитом через инструменты хоста; проекты с обязательными hooks/подписью требуют соответствующего отдельного процесса. Обычные фильтры Git при staging и переключении веток сохраняются: они могут запускать настроенные программы и обращаться к сети, например через Git LFS. Git также может получать недостающие объекты в partial clone.
- Запросы этого сервера выполняются последовательно. Один процесс Git ограничен 15 секундами и 512 КБ вывода; большой запрос нужно сузить по путям или числу коммитов. Сообщения и имена файлов обрабатываются как UTF-8.
- MCP-сервер имеет файловые права запустившего его процесса; sandbox чата не является дополнительной изоляцией сервера. По умолчанию можно явно выбрать любой доступный локальный репозиторий.

Для ограничения доступа задайте окружение сервера:

| Переменная | Значение |
| --- | --- |
| `GIT_MCP_READ_ONLY` | `true` или `1` запрещает все изменяющие инструменты |
| `GIT_MCP_ROOTS` | Разрешённые абсолютные каталоги через разделитель путей ОС: `:` в macOS/Linux, `;` в Windows |

Например, добавьте в запись сервера в `plugins/git-mcp/mcp.json` поле:

```json
"env": {
  "GIT_MCP_READ_ONLY": "true",
  "GIT_MCP_ROOTS": "/Users/me/projects"
}
```

Корень целевого рабочего дерева должен находиться внутри одного из разрешённых каталогов. Символические ссылки разрешаются перед проверкой. Это ограничение выбираемых рабочих деревьев, а не sandbox для Git и настроенных фильтров.

## Разработка и проверка

```sh
npm ci
npm run check
```

`npm run build` собирает сервер вместе с зависимостями в `plugins/git-mcp/dist/server.cjs` и сохраняет лицензии включённых пакетов в `plugins/git-mcp/dist/THIRD_PARTY_NOTICES.txt`. Храните каталог `plugins/git-mcp/dist/` в репозитории: установленный плагин запускает именно эту сборку. `npm test` предполагает, что сборка уже актуальна; `npm run check` пересобирает её перед тестами.

Тесты создают временные Git-репозитории, проверяют операции и полный обмен MCP через stdio. Они не изменяют историю текущего проекта и не используют удалённые серверы.

Структура:

```text
.agents/plugins/marketplace.json  Каталог для установки плагина
plugins/git-mcp/
  plugin.json                    Идентификатор и метаданные Codex
  mcp.json                       Запуск локального MCP-сервера
  skills/                        Три навыка с метаданными интерфейса
  dist/                          Самодостаточная сборка
src/                             Git-операции, схемы инструментов, MCP-сервер
test/                            Интеграционные проверки
```

Формат упаковки и установки следует [документации плагинов OpenAI](https://developers.openai.com/plugins/build/plugins); `${PLUGIN_ROOT}` и локальный запуск описаны в [документации desktop-only плагинов](https://developers.openai.com/plugins/deploy/desktop-only). Публикация в публичном каталоге — отдельный процесс; этот репозиторий подготовлен для локальной установки.
